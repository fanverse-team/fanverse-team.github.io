# FANVERSE 追星人的第二個家

智慧商業：人工智慧與創新應用 期末專題（第 11 組）

網站：https://fanverse-team.github.io/

## 功能

- **演唱會情報站**：真實場次（台北大巨蛋、台北小巨蛋、北流、高雄巨蛋、高雄國家體育場），依韓流／日本／華語／歐美／綜合分類，含票價、售票平台、交通、住宿、散場動線
- **同行媒合**：包車共乘、住宿分攤、旅伴配對，採申請／接受制
- **團體空間**：成團後，發起人與已確認的成員共用一個聊天室（最近 60 則、每則 300 字、同一人 2 秒內只能發一則）和一份共用行程（發起人設定，全團都能下載同格式的行程圖）；可疑訊息會自動提醒，可檢舉
- **多團衝突檢查**：同一場、同一天的包車與住宿各只能確認一團（資料庫規則強制）；同一天兩場演出若開演時間都已公布且時段重疊（以 3 小時計）就不能同時報名或發起；同一天不同城市、或有一場未公布時間，會先跳提醒；等待確認中的同行申請每人最多 5 筆；有新訊息時「我的」分頁與團體空間按鈕會出現紅點
- **周邊交換**：交換、出售、徵求，可上傳照片
- **追星小幫手**：依出發地、交通方式、住宿與預算排出時間軸與花費估算；讓票防詐檢查（皆為規則式）
- **實名帳號**：Email 登入＋信箱驗證＋實名資料

## 資料怎麼自動更新

`.github/workflows/update.yml` 每天兩次（台灣時間 05:17、17:17）在 GitHub 上執行 `scripts/update.mjs`，不需要任何人手動操作，也不需要付費服務。

| 資料 | 來源 | 頻率 | 寫入 |
|---|---|---|---|
| 場次與日期 | 台北小巨蛋、北流官網；台北大巨蛋、高雄巨蛋、高雄國家體育場的維基百科演唱會列表 | 每天兩次 | `concerts.json` |
| 票價、售票平台、這場的售票頁 | Bing 新聞搜尋找到的報導，必須同時對上場館與日期才採用 | 沒票價的場次每 3 天找一次，已找到的每 14 天複查 | `concerts.json` |
| 場館附近住宿 | OpenStreetMap（依距離排序） | 每週 | `hotels.json` |

- 自動擷取的票價會在網站標示「系統從新聞自動擷取，可能有誤」並附來源；人工填的票價不會被覆蓋
- 房價不存檔：每間住宿都附「查演出當天入住的即時房價」連結，直接看訂房網當天的價格
- 網站不顯示剩餘票數或是否完售（變動太快、售票平台不開放抓取），一律請使用者點售票頁查看
- 某個來源抓不到時沿用舊資料；想立刻更新：到 Actions →「更新場次資料」→ Run workflow
- 想手動修正：直接編輯 `concerts.json` 那一筆（例如 `genre`、`price`、`prices`），之後的自動更新不會蓋掉人工填的票價

## 實名制與隱私設計

| 資料 | 儲存位置 | 誰看得到 |
|---|---|---|
| 身分證字號 | **不儲存**（只在使用者裝置檢查格式與性別碼） | 無 |
| 真實姓名、出生日期 | `private/{uid}` | 只有本人；姓名可由本人逐一揭露給確認同行／交易的對象 |
| 暱稱、性別、年齡區間 | `users/{uid}` | 完成信箱驗證的登入會員 |
| 申請紀錄 | `rides/{id}/requests/{uid}`、`trades/{id}/interests/{uid}` | 申請者本人與發起人 |
| 實名揭露 | `reveals/{owner}/to/{viewer}` | 揭露者與被揭露的那一位 |
| 聊天訊息、共用行程 | `rides/{id}/chat/*`、`rides/{id}/meta/plan` | 發起人與已接受的成員 |
| 檢舉 | `reports/{檢舉人_訊息}` | 沒有人能從網站讀取，只能在 Firebase 主控台 → Firestore 查看 |

未成年（13–17 歲）：需法定代理人同意；姓名與年齡不公開；不能發起或參加住宿分攤（由安全規則強制）。未滿 13 歲不能註冊。

## 安全措施

- Firestore 安全規則（`firestore.rules`）：預設全部拒絕、每個欄位驗證型別與長度、實名資料只有本人可讀、姓名與生日建立後不可修改、未成年限制在伺服器端執行
- 必須完成信箱驗證才能讀寫會員資料
- Firebase 密碼政策：至少 10 碼，需含大小寫英文與數字；開啟電子郵件列舉防護
- CSP 禁止內嵌腳本，所有使用者內容輸出前跳脫，降低 XSS 風險
- 上傳照片在裝置端以 canvas 重新編碼，移除 EXIF（含 GPS）
- 使用者可自行刪除帳號與所有資料（個資法第 3 條權利）
- Firebase App Check（reCAPTCHA Fraud Defense）：資料庫已「強制執行」，只接受本網站送出的請求，擋掉機器人與盜用。驗證有效期一天，每月前 10,000 次驗證免費；登入（Authentication）的強制執行目前是預先發布版，尚未開啟

## 已知限制

- 檢舉沒有自動處理，需要管理員定期到 Firebase 主控台查看 `reports`
- 場次不是即時資料：每天更新兩次，維基百科來源為社群維護，購票前仍須以主辦與售票平台公告為準
- 自動擷取的票價可能有誤；住宿名單來自 OpenStreetMap，可能缺漏新開的旅館
- 交通時間與行程花費為概略估算

- 身分證只做格式檢查，無法確認是否為本人（內政部查驗 API 僅開放依法須查驗的機構申請）
- 尚未做手機簡訊驗證（Firebase 簡訊需付費方案）
- reCAPTCHA 每月免費 10,000 次驗證；超過時會員功能可能暫時無法使用，可到 Firebase → App Check 暫停強制執行

## 檔案

- `index.html`：網站本體（程式與 Firebase 網頁設定都內嵌在裡面，用 CSP 雜湊值只允許這段腳本執行；Firebase 設定是公開值，不是密碼）
- `styles.css`：樣式
- `privacy.html`：個人資料蒐集告知暨隱私權政策
- `firestore.rules`：資料庫安全規則（已發布到 Firebase，此檔供備查）
- `concerts.json`：場次資料（排程自動更新，可手動修正）
- `hotels.json`：各場館附近住宿（排程每週自動更新）
- `scripts/update.mjs`：自動抓取程式
- `.github/workflows/update.yml`：排程設定
