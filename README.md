# FANVERSE 追星人的第二個家

智慧商業：人工智慧與創新應用 期末專題（第 11 組）

網站：https://fanverse-team.github.io/

## 功能

- **演唱會情報站**：真實場次（台北大巨蛋、台北小巨蛋、北流、高雄巨蛋、高雄國家體育場），依韓流／日本／華語／歐美／綜合分類，含票價、售票平台、交通、住宿、散場動線
- **同行媒合**：包車共乘、住宿分攤、旅伴配對，採申請／接受制
- **周邊交換**：交換、出售、徵求，可上傳照片
- **追星小幫手**：依出發地、交通方式、住宿與預算排出時間軸與花費估算；讓票防詐檢查（皆為規則式）
- **實名帳號**：Email 登入＋信箱驗證＋實名資料

## 場次資料怎麼更新

`.github/workflows/update.yml` 每天兩次（台灣時間 05:17、17:17）在 GitHub 上執行 `scripts/update.mjs`，把結果寫進 `concerts.json`，網站開啟時讀這個檔。不需要任何人手動操作，也不需要付費服務。

| 場館 | 自動比對的來源 |
|---|---|
| 台北小巨蛋 | 場館官網「已公開活動」 |
| 台北流行音樂中心 | 場館官網節目列表（表演廳的演唱會） |
| 台北大巨蛋、高雄巨蛋、高雄國家體育場 | 維基百科各場館條目的演唱會列表（官網沒有可讀的列表） |

- 來源出現新場次 → 自動新增，並依藝人自動分類；來源的日期改了 → 自動更新日期
- 票價、售票平台、開賣時間不在這些來源裡，仍要人工補進 `concerts.json`（人工填的欄位不會被覆蓋）
- 某個來源抓不到時沿用舊資料；人工整理的場次不會被自動刪除
- 自動分類錯了，直接改 `concerts.json` 裡那一筆的 `genre` 即可
- 想立刻更新：到 Actions →「更新場次資料」→ Run workflow

## 實名制與隱私設計

| 資料 | 儲存位置 | 誰看得到 |
|---|---|---|
| 身分證字號 | **不儲存**（只在使用者裝置檢查格式與性別碼） | 無 |
| 真實姓名、出生日期 | `private/{uid}` | 只有本人；姓名可由本人逐一揭露給確認同行／交易的對象 |
| 暱稱、性別、年齡區間 | `users/{uid}` | 完成信箱驗證的登入會員 |
| 申請紀錄 | `rides/{id}/requests/{uid}`、`trades/{id}/interests/{uid}` | 申請者本人與發起人 |
| 實名揭露 | `reveals/{owner}/to/{viewer}` | 揭露者與被揭露的那一位 |

未成年（13–17 歲）：需法定代理人同意；姓名與年齡不公開；不能發起或參加住宿分攤（由安全規則強制）。未滿 13 歲不能註冊。

## 安全措施

- Firestore 安全規則（`firestore.rules`）：預設全部拒絕、每個欄位驗證型別與長度、實名資料只有本人可讀、姓名與生日建立後不可修改、未成年限制在伺服器端執行
- 必須完成信箱驗證才能讀寫會員資料
- Firebase 密碼政策：至少 10 碼，需含大小寫英文與數字；開啟電子郵件列舉防護
- CSP 禁止內嵌腳本，所有使用者內容輸出前跳脫，降低 XSS 風險
- 上傳照片在裝置端以 canvas 重新編碼，移除 EXIF（含 GPS）
- 使用者可自行刪除帳號與所有資料（個資法第 3 條權利）

## 已知限制

- 場次不是即時資料：每天更新兩次，維基百科來源為社群維護，購票前仍須以主辦與售票平台公告為準
- 交通時間、票價、住宿價位為概略估算

- 身分證只做格式檢查，無法確認是否為本人（內政部查驗 API 僅開放依法須查驗的機構申請）
- 尚未做手機簡訊驗證（Firebase 簡訊需付費方案）
- 尚無伺服器端頻率限制；正式上線前建議開啟 Firebase App Check

## 檔案

- `index.html`：網站本體（程式與 Firebase 網頁設定都內嵌在裡面，用 CSP 雜湊值只允許這段腳本執行；Firebase 設定是公開值，不是密碼）
- `styles.css`：樣式
- `privacy.html`：個人資料蒐集告知暨隱私權政策
- `firestore.rules`：資料庫安全規則（已發布到 Firebase，此檔供備查）
